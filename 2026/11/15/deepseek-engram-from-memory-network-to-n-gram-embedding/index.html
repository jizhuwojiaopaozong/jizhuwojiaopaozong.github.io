1. Engram 想解决什么问题

DeepSeek 这篇名为 Engram 的论文，针对的是 Transformer 架构的 Memory 问题：让这类架构做更高效的 Knowledge Retrieval（知识检索）。这个领域里已经有大量引入或改进 Transformer Memory 的工作，Engram 是这条脉络的延续，很多想法直接来自前序工作。

它的解题思路一个词就能概括：引入 Sparsity（稀疏性）。为什么要稀疏？因为大家还想继续沿用 Scaling Law 把模型做大，而早期的 Dense 模型头上悬着一个不可能三角：模型的 Performance、Compute Cost（FLOPs）、Model Size 三者很难同时优化——想让性能上升，要么加参数、要么加计算，几乎不可能在提升性能的同时把另外两个降下来。

稀疏化的作用就是把这个三角的边切断。MoE 架构让 Model Size 和 Compute Cost 解耦：参数量增加时，计算量可以被控制住不跟着涨。把 DeepSeek 前几篇论文排开看，Sparsity 这条主线贯穿始终：

  • MoE 论文：把 Transformer 的 MLP 层换成多个更小的 expert MLP，激活时只计算一部分参数，实现 Sparse Compute
  • V3 论文：在 Attention 侧引入 MLA，本质是 low rank 分解——计算更小的矩阵而不是原始大矩阵，思路上与稀疏相近
  • 随后的 Sparse Attention（DSA）：在 Attention 侧直接应用稀疏化
  • 这篇 Engram：回到 MLP 一侧继续改进——虽然 MLP 已经换成 MoE，但 basic knowledge 仍要靠计算得出，非常低效，于是加入 Engram 模块用 hash 查表做知识提取

记住这个就够了：DeepSeek 全系列的核心思想是 Sparsity，目的是绕开 Performance/Compute/Size 的不可能三角继续 scale up；Engram 是这条主线在 MLP 一侧的最新落子。

2. 九九乘法表类比

人计算 $324 \times 78$ 这样的多位数乘法时靠两种能力：一是九九乘法表，小学就背下来了，遇到 $4 \times 8$ 直接说出 32——这是存在 Memory 里的知识；二是进位、先算哪一位再算哪一位这些规则——这是 Reasoning。

现在的 Transformer 架构恰恰缺了 Memory 这一半。它像一个没背乘法表的人：遇到 $4 \times 8$ 只能现场算 $8+8+8+8$。凡是本可以查表的简单操作都要重新计算一遍，浪费大量计算资源。

Engram 的做法：把这类 knowledge 做成一个巨大的 Embedding 表放进模型，需要时直接查。打个比方： 这等于给模型发了一张九九乘法表小抄，模型需要时就去小抄里查，而不是每次现推。有了背景知识之后再看这篇论文，会发现核心思想就是这么简单。

记住这个就够了：Engram 的核心思想 = 让模型对静态知识从「每次现算」变成「直接查表」，把算力省下来留给真正的推理。

3. Engram 一词的由来

DeepSeek 在这里玩了一个谐音梗，一词双关。第一层：Engram 发音很像 N-gram——NLP 领域早期的经典方法，这是论文的技术支线之一。第二层：Engram 本身就是个真实的科学词汇，意思是「记忆」。

20 世纪初，科学家 Richard Semon 提出了这个词：他认为大脑中存在一种 neural substrate（神经基础）负责存储和提取记忆——某些神经元细胞经过化学或物理改变成为 Engram，保留了记忆；当相关线索被提起时，这类细胞被重新激活，实现 memory retrieval。这个概念长期不被认可，Semon 郁郁不得志最终自杀；后续科学家寻找 Engram 细胞的证据也失败了很长时间。转机来自光遗传学等新技术，实验终于找到了这类细胞：在特殊染色的图像里，记忆被唤醒时呈现粉红色的神经元就是 Engram 细胞，旁边未唤醒的则是 Non-Engram 细胞。

所以 DeepSeek 用这个词非常贴切：机制上对应 N-gram 查表，语义上对应「模型里的记忆细胞」。

记住这个就够了：Engram = N-gram 的谐音 + 神经科学中真实存在的「记忆细胞」，这个词本身就预告了论文的两条技术支线。

4. FFN 层就是 Key-Value Memory

第一条支线：Memory 方向的工作。Transformer 提出后大家其实并不理解它为什么有效，于是反过来研究它的原理，几篇论文层层递进。Facebook 2019 年提出语言模型本身就可以作为 Knowledge Base——在此之前 NLP 做知识库的常用方法是 Knowledge Graph（节点和边表示知识关系，给定 query 去图里提取答案），而基于 Transformer 的语言模型（如 BERT）已经能把知识存在参数里，不再需要外部的图。Google 2020 年对 T5 得出类似结论，并且说了一句很关键的话：模型回答一些问题不需要外部知识或 context，直接 lookup 参数中存储的信息——这正是 Engram 想做的事的雏形。

但知识到底是怎么存的？2021 年的一篇论文给出了奠基性回答：FFN 层就是一个 key-value memory。FFN 一般有两层参数：第一层参数当 key，第二层参数当 value。输入先与第一层参数做矩阵乘法，本质是内积、是相似度计算——在参数记住的各种 pattern（比如 “It will take a”、”every once in a”）里找和输入 pattern 相似的，得到权重（不像的 pattern 权重接近 0，像的可能 1.5）；然后用这个权重对第二层的 value 做加权平均，把知识提取出来（比如输入 “Stay with you for…” 时，”while” 对应的 value 权重最大，被查询出来）。

打个比方： 去图书馆借书——第一层参数是书的 index（key），第二层参数是书的内容（value），有了 index 就能快速找到书。

微软 2022 年再进一步，提出知识神经元（Knowledge Neurons）：FFN 里特定的神经元对应特定的知识，问 Ireland 的首都，一组特定神经元被激活，然后回答 Dublin。注意这里所有的 key 和 value 都是可学习参数，靠反向传播更新。

问题也随之暴露：这种存取知识的方式每一层都要经过大量计算，即使后来有些工作把过程变稀疏，仍然要算。DeepSeek 的追问是：像「Ireland 的首都」这种相对固定的知识，能不能直接搞一个参数表，用时查询，跳过 FFN 的大量计算？另一篇提出 Concept Depth（概念深度） 的论文佐证了这个动机：简单 task 在浅层就能形成概念，复杂 task 要到深层才能形成，弱一点的模型可能走到最后一层概念还没形成——对常识而言，逐层计算这种方式本身就不划算，直接放外部 memory 里让模型去提取就好。

记住这个就够了：FFN 层本质是 key-value memory（一层参数是 key、二层参数是 value），知识神经元是它的细化；但靠计算提取知识太贵、深概念还受层数限制——这就是 Engram 的动机。

5. PKM 与稀疏 Memory Layer

Facebook 2019 年的另一篇论文提出了 Product Key Memory（PKM），后续大量 Transformer Memory 工作都是对它的改进，Engram 里也能看到很多它的思想。这篇论文有三个重要贡献：

  • 提出了一个独立的 Memory Layer——之前的工作还在 FFN 上做文章，它单独造了一层
  • 把 dense memory 变成 sparse memory：原始 FFN 里所有 key 都会参与计算（只是权重有大有小），sparse memory 则是给定 query 只用少部分 top-k 的 key，不相关的 key 压根不碰，计算量显著减少——和 MoE 的道理一样
  • 引入了 lookup（查表）机制，让查 key 非常高效——DeepSeek Engram 正是基于这种思想，只不过 PKM 用 product key 查表，DeepSeek 用 hash 查表

基本流程：输入先经过一个 query network（可以就是一个简单线性层做 projection）映射成 query；用 k-nearest-neighbor 在 key 里找 top-k（比如 top-2）；取出对应的 value 做加权平均输出。

瓶颈在于 key 可能非常庞大——图书馆里书太多，index 太多，拿 query 逐个比对会非常慢。product key 的办法是「切分」：假如原始 key 是 128 维向量，从中切成两半，前一半作为第一套子 key、后一半作为第二套子 key；query 也同样切开，前半查第一套、后半查第二套，最后把结果组合。每套子 key 只有很少的可能（比如各 3 种），但两套的排列组合（外积）能表达巨大的 key 空间——想象一个矩阵，行向量和列向量的组合覆盖整个矩阵。这样就极大减少了需要存储和比对的 key 数目，查询速度大幅提升。用法是在某些层把 FFN 换成 PKM layer。

记住这个就够了：PKM 用「子 key 切分 + 组合」的查表方式实现了稀疏 key-value memory，让 Memory Layer 既省计算又能做大——Engram 继承了查表思想，只是把 product key 换成了 hash。

6. 门控、外部记忆与 Memory 支线总结

Meta 随后把 memory layer 继续 scale up，一路做到 128B 的 memory 参数——相当恐怖。之所以能这么大，正是 key-value lookup 机制：可以不断增加可训练参数去存储和提取信息，却不增加模型的 FLOPs。这篇论文还对原始 memory layer 做了一个改进：在旁边加了一个 gating（门控），对 memory layer 提取出的信息做进一步筛选——提取结果可能有噪音或不准确，用门控再过滤一遍。这个 gating 机制后来被 DeepSeek Engram 直接沿用，可见这个领域的工作是连续、有传承的。

前面都是拿网络参数当 memory；能不能拿外部数据当 memory（类似 RAG）？可以，而且工作不少。代表是 DeepMind 2022 年的 RETRO：把 input tokens 切成 chunk（讲者认为这种切法和 Engram 的 chunk、和 N-gram 本质非常像，区别只是 N-gram 要做 sliding window 枚举所有组合，这里直接切），用训练好的 BERT 在外部 database 里 retrieval 最相近的 key-value，再送进 cross-chunk attention 与输入 query 做 attention，把外部信息注入 Transformer。注意这里的外部信息是固定的、不可训练的。

最后用 Google 2023 年的一篇论文给整条支线收束——它的核心思想也是 Engram 的核心思想：如果能给大语言模型一个巨大的、含参数的 external table，并且有一种足够快的 sparsely lookup 方法，就能在不影响推理时间的前提下极大提高模型的 predictive capacity。额外的参数有两种用法：一是做更丰富的 input representation——映射到 Engram，就是用 N-gram 表征输入；二是把 table 理解为 expert function，那就是 MoE 的变种。查表方式也有多种：routing function（MoE 用的）、直接用 token id、hash function、softmax——只要足够快就行。DeepSeek 选了最简单的 hash function。

记住这个就够了：Memory 支线的终点是一句话——「巨大的外部参数表 + 便宜的稀疏查表」；Engram 就是这句话的工程实现，gating 和 offload 思想也早在这条支线里出现过。

7. 从条件概率到 N-gram 查表

第二条支线：N-gram。讲者读 PhD 时就用 N-gram 的统计方法给 DNA 数据建模，这是他很熟的领域。语言建模本质是学一个条件概率：给定一段话，下一个词是什么的概率。比如 “The water of Walden pond is so beautifully” 后面出现 blue 的概率是多少。

难点在于 high dimension（高维）：一句话后面可接的词非常多，每种可能算一维，这就是高维问题。高维空间里估计东西需要海量数据，而且直觉会失效。打个比方： 讲者老师举过的「酒鬼随机游走」——一维空间里喝醉的人随机左右走，一定能回到家；二维里上下左右随机走，也一定能回到；但到三维，就不一定了，回家概率不再是 1。维度升高会改变问题的性质。

所以早期 NLP 把问题一步步简化：

  • Bag of words：不考虑条件概率，把每个词当独立出现，只数词频。代价是 “dog bites man” 和 “man bites dog” 结果完全一样——词与词之间的语序关系被忽略了
  • N-gram：不完全忽略语序，但也不看整句，只看最相邻的前一个（或前几个）词，即马尔可夫假设——把原始条件概率近似成「只看最后一个词和 blue 之间关系」的 2-gram 条件概率

具体用法就是建一张计数表：数出语料里各种 n-gram 的出现次数，按总次数做 normalization 得到概率。比如 $P(\text{i want})=0.33$ 很大，$P(\text{i to})=0$ 即没有这种搭配，$P(\text{i eat})$ 出现了但概率较小。有了表，实际用的时候直接查表——这和 DeepSeek Engram 的思想非常像，区别只在于 Engram 的表里存的不是简单的 probability 而是 vector，好处是把 n-gram 映射进了语义空间（word2vec 的思想）。

记住这个就够了：N-gram 用马尔可夫假设把高维条件概率问题变得可解，产物天然就是一张「建表 + 查表」的概率表——这是 Engram 基因的另一半。

8. N-Grammer 把 N-gram 塞回 Transformer

Transformer 类大模型提出后，N-gram 销声匿迹了一段时间，直到 2022 年 Google 发表 N-Grammer：用 latent 的 n-gram 增强当前的 Transformer。动机和 Engram 如出一辙：想更好地 scale up 模型，于是把 n-gram representation 整合进模型，同时借用 Memory 支线的方法让整个过程是 sparse operation，embedding lookup 的开销特别小。本质上这是一个用 n-gram 方式 augment 的 memory augmented model。

以 bigram（两个 token）为例，整体流程：

第一道坎是词表爆炸：unigram 词表大小是 $V$ 的话，bigram 词表就是 $V^2$。原始词表 32000，bigram 就是约 10 亿（billion 级），没法做。作者的解法是codebook 降维：对 token embedding 做 k-means clustering，聚成 4096 个类，每个 cluster 就是 codebook 里的一个 vector——直观上就是把语义相似的 token 聚到一起用一个 id 表示。词表从 32000 压到 4096 后，bigram 词表变成 $4096^2$≈1600 万（16 million），量级可以接受了。组合方式也简单：把相邻两个 token 离散化后的 codebook id 拼在一起，就是一个新的 bigram id。

第二道坎是大表查询慢：1600 万行的 embedding 表，逐行找太慢。解法是 hash：hash 查询的算法复杂度是 $O(1)$，具体 hash function 就是对随机质数取模，非常常规。最后把查到的 bigram embedding 和最初的 unigram embedding concatenate 起来，输出既含原始 unigram 信息也含 bigram 信息。值得强调：这里的 bigram embedding 是 trainable 的——这一点和 DeepSeek Engram 完全一样。

记住这个就够了：N-Grammer = codebook 聚类降维解决 n-gram 词表爆炸 + hash 实现 $O(1)$ 查大表 + 与 unigram embedding 拼接；这两板斧 Engram 全都接了过去。

9. 方法论插曲：化简为繁与化繁为简

讲者在这里做了一个思想实验，回应「科研思路从哪来」：假设有时光机回到 2022 年 N-Grammer 刚发表时，我们能不能自然想到 Engram 的想法？前提是两条：第一，对相关领域的 background 要非常熟——不必知道每篇论文的细节，但每个 idea 以及 idea 之间的关系要熟到成为大脑里的 memory，遇到相关问题立刻激活对应的知识图；第二，批判地读论文——看完除了拍手称好或大骂垃圾，还要想它能不能改进。改进的基本思路有两个方向：

10. f-gram 与更大的 Embedding 层

Google 2025 年的文章继续沿用 n-gram 思想，主题是 scaling up embedding layer。做法：给定 input text，产生 unigram token 后，找出对应的各种 n-gram（unigram、bigram、trigram 都包括），但只统计其中经常出现的那些，称为 f-gram，把 f-gram 挑出来；然后经过一个 embedding transformer，得到融合后的 embedding，再送进标准 Transformer。宏观上看，这相当于把一个 memory layer（或者说新的 embedding layer）插进了原始模型。

这篇论文有个值得注意的点：embedding table 是可以 pre-computed 并且在推理时 offload 的。所以 DeepSeek Engram 论文里提到他们的方法可以 offload 到 CPU memory，并不是什么新鲜想法——这里早就提过了。除了 f-gram 之外，其它想法与前面的工作非常类似，讲者不再展开。

至此两条支线交汇：Memory 支线虽然没怎么提 n-gram，但 n-gram 支线的工作大多借用了 Memory 支线里巨大 embedding table、lookup 机制这些思想。背景铺垫完成，Engram 论文本身反而简单了。

记住这个就够了：f-gram = 只把高频 n-gram 放进表里；embedding 表可预计算、可 offload——这两点一个指向 Engram 的工程形态，一个指向讲者后文提出的改进方向。

11. Engram 架构：用查表实现条件记忆

回到正题。Engram 论文的 motivation：给 Transformer 这样的模型建立一个 conditional memory（条件记忆），用 n-gram embedding 实现，并使用各种 lookup 机制让查找在 $O(1)$ 复杂度内完成。这里有个重要的概念区分：现在的大语言模型其实在做两件事——Reasoning 和 Knowledge Retrieval。而现有架构里知识检索仍要靠计算（simulating retrieval through computation），就像不背九九乘法表的人连简单乘法都要现推。

架构图一看就能和前面的 Memory 工作联系起来：这就是一个 memory layer，只是插的位置不同——Google 是把 embedding layer 插在模型前端，DeepSeek 放在这个位置，也可以理解为 Google 那个 embedding layer 的变种。Engram layer 做的事就是 n-gram 查表，用了 2-gram 和 3-gram 的结合（讲者认为把二者合到一起是这篇论文相对新颖的点）：给定输入，既查它对应的 2-gram 也查 3-gram，全部用 hash function 查，速度约 $O(1)$；查到的 embedding 直接 concatenate，然后进入 gating。

gating 部分是一个类似 attention 的结构：查出来的 embedding 经过两个 linear projection，一个的输出当 value，另一个当 key，原始输入当 query；scaled dot product 算出一个 **$\alpha$**，就是门控值；$\alpha$ 和 value 相乘，控制多少 n-gram 信息进入输出——$\alpha$ 越大，进入的信息越多。最后还加了一个 convolution，讲者认为起 smoothing 或 fusion 作用，但作者自己的 ablation study 也说了这个 convolution 有没有影响不大，不是关键。为避免 hash 常见的 collision，用了多个不同的 hash function——这是 hash 的常用做法。整套设计正是 sparsity 思想的又一次落地：查表引入大量参数，计算量却很小。

训练与推理的形态不同：training 时巨大的 embedding table 在不同 GPU 之间 share；inference 时可以 offload 到 CPU memory。DeepSeek 还由此提出 memory hierarchy（记忆层级） 分层机制：常见的 n-gram 放比较快的内存，不常见的放比较慢的内存。

和前序工作对照着看：n-gram lookup + gating 把 local dependencies（固定搭配）直接提取出来，网络不再需要对这些固定搭配做 key-value 式的计算；还记得概念深度那篇论文说复杂观念要到很深的层才能学会吗——这种方式恰好避免了那个问题。

记住这个就够了：Engram = 2-gram/3-gram 多头 hash 查表 + attention 式 gating 控制信息量；把知识检索从逐层计算变成 $O(1)$ 查表，训练时跨 GPU 共享大表、推理时可 offload 到 CPU 并按冷热分层。

12. 工程细节：tokenizer 压缩与多头 hash

第一个细节是 tokenizer compression（词表压缩）：原始 tokenizer 会把不同大小写、不同拼写形态的 token 当成不同 token；DeepSeek 把它们统一成一个——各种各样的 a 都归成 a，各种各样的 o 都归成 o，从而压缩 tokenizer。对比 N-Grammer 用 codebook（k-means 聚类）做压缩，DeepSeek 用了更简单的规则方法，但目的完全一样：让 vocabulary size 更小，后面算 n-gram 时相对容易——这正是第 9 节方法论里「化繁为简」的实例。

第二个细节是查表：DeepSeek 沿用前人思想做 hash，为避免 collision 用了 multi-head 的 hash n-gram，且每一路的 hash 方式就是非常简单的异或。和 PKM 的 product key 切分查询不同，这里直接对离散的 n-gram 做 hash 定位，更简单也更快。

第三个细节是 gating 的可视化证据：论文用热力图展示 gating 里的 $\alpha$，红色越深表示 $\alpha$ 越大（看的时候要把前面的 token 和后面一系列 n-gram 连起来看）。结果是 gating 确实学出了大量固定搭配：英文里的 Diana 与 the princess of Wales；中文里的「四大」与「发明」、「造纸」与「术」、「指南」与「针」、「印刷」与「术」、人名「仲景」与「张」。

有了 n-gram lookup 和 gating，网络就不需要再对这些固定搭配做前面 key-value memory 里那种计算了。

记住这个就够了：三个工程动作服务于同一个目标——表更小（tokenizer 规则压缩替代 codebook）、查得快且无冲突（multi-head hash 异或）、用得稳（gating 学出固定搭配、过滤检索信息）。

13. 实验结果：U 型分配与消融

先看 MoE 与 Engram 的算力分配。同样 compute budget 下，两者的比例呈现一条 U-shape 曲线：横坐标是 allocation 百分比，纵坐标是 validation loss（越低越好）。右端是没有 Engram layer 的纯 MoE；左端 MoE 占 40%、60% 时性能反而差；最好的区间在 MoE 占七八成、Engram 占两三成左右。这背后仍是不可能三角的变体：算力固定时，MoE 和 Engram 抢的是同一份 sparsity 预算。作者的说法是 Engram 是 MoE 的 complement（补充）——也有一些工作提到 memory network 和 MoE 有等价之处，把 Engram 看成 memory network 的变种的话，它就是 MoE 的某种特殊形式；两者都提供 sparsity，所以存在一个分配的 sweet spot。讲者坦言对 U-shape 背后的深层原因想得不是很清楚，欢迎读者留言讨论。

Scaling law 实验：把 Engram 的 embedding matrix 不断做大（参数达到 $10^7$量级），模型性能不断提高。这类实验在 memory network 等前序工作里很多人做过——scale up external table 能有效提升 Transformer 性能，同时不引入更多 compute。

模型对比：dense model、MoE model、Engram model 在不同任务上比，MoE 好于 dense，Engram 基本上在所有任务上超越 MoE；把 Engram 从 27B 做到 40B，性能还有进一步提高。

Ablation study：以带 Engram 的完整版为 100% 基准，把 Engram 模块整个去掉，看各任务性能下降多少。最右边需要 factual knowledge 的任务下降最多；其次是算法、数学类的 reasoning 任务，下降也非常多；而需要较多阅读理解、或只靠常识推理的任务下降不明显。这说明 Engram 对知识的存储和提取类任务非常关键——这和知识神经元的观察相呼应：事实性知识本来就适合定位化存储，Engram 给了它一个更直接的存放处。

记住这个就够了：MoE 管条件计算、Engram 管条件记忆，固定算力下约「MoE 七八成 + Engram 两三成」最优；scaling 大表持续涨点，消融证明 Engram 贡献最大的是事实性知识。

14. 总结与展望

讲者的整体判断：这篇论文理解起来不难，前提是你熟悉领域内两条支线的相关工作——memory network / memory layer 一类，和 n-gram 一类。Engram 基本就是前人工作的集合：external memory 查表、offload 到 CPU memory 都是前人提出过的；稍微不一样的点是把 2-gram 和 3-gram 合到了一起。他不认同部分自媒体「惊天地泣鬼神、新 Transformer 架构」的说法，但也不贬低这篇论文——科研本来就是循序渐进，每篇论文都是对前人工作一点点小的修改，累积多了形成质变。

这篇工作还能怎么改进？讲者给了几个方向：

  • 表还是太大：Engram embedding 虽然能 offload 到 CPU memory，但考虑 3-gram 之后仍是一张特别大的表——可以结合前面的 f-gram 思想，只把高频出现的 n-gram 提取进表，让表更小；查表虽快，存储本身也要资源
  • 压缩表：利用 low rank 或 sparsity 性质压缩，比如借鉴 codebook——语义空间内相似的 engram 聚合在一起表征，减少表格整体维度
  • 可编辑的 memory：有了外部 embedding 表格，就很容易通过各种方法找到对应的概念，直接修改、添加或删除它的 memory，不用重新训练 Transformer——这是领域内很大的一块研究方向
  • 更宏观的问题：大家现在仍沿着 Scaling Law 的思路 scale up Transformer 的各个部分；Engram 本质是加了更多可 lookup 的参数、计算量却不大。在数据一定、算力很难再增长的情况下，还有没有其它巧妙改进架构使其更容易 scale up 的方式——这是下一个研究的关键

记住这个就够了：Engram 是两条支线的集大成而非横空出世；它的下一步是让表更小（f-gram）、可压缩（low rank/codebook）、可编辑（免重训更新记忆），以及探索 scale up Transformer 的新路径。

自测题（面试速答）

  1. Dense 模型面临的不可能三角是什么？引入 sparsity 为什么能打破它？（对应：不可能三角）

答案： 不可能三角指 Performance、Compute Cost、Model Size 三者难以同时优化，想提性能就得加参数或加计算。Sparsity 把其中 Model Size 与 Compute Cost 这条边切断了：参数可以很多，但每次前向只激活或只查询其中一小部分，计算量不随参数量增长。MoE 是典型例子——expert 很多但只激活 top-k；Engram 也一样，embedding 表可以做到上百 B 参数，用的时候只是 $O(1)$ 查表，几乎不加 FLOPs，于是 Scaling Law 可以继续往上 scale。

  1. 为什么说 Transformer 的 FFN 层本质是 key-value memory？key 和 value 分别对应什么？（对应：Key-Value Memory）

答案： 因为 FFN 的计算过程可以解释为一次「按键取值」：第一层参数是 key，第二层参数是 value。输入与第一层参数做内积，本质是相似度计算，在参数记住的各种 pattern 里找出与输入相近的，得到权重；再用权重对第二层的 value 做加权平均，把知识提取出来。比如输入 “Stay with you for…” 时，”for a” 这类 pattern 权重变大，对应的 value “while” 就在输出里占主导。图书馆的类比是：一层参数是书的 index，二层参数是书的内容。

  1. PKM 的 product key 设计解决了什么问题？它是怎么工作的？（对应：Product Key Memory）

答案： 它解决的是 key 空间巨大导致查询太慢的问题。做法是把原始 key 向量（如 128 维）从中切成两半，作为两套子 key；query 也同样切开，前半查第一套、后半查第二套，最后组合结果。每套子 key 只有少量可能，但两套的排列组合（外积）能表达巨大的 key 空间，因此存储和比对的 key 数目大幅减少、查询显著加速。PKM 还引入了独立 memory layer、sparse top-k 取值和 lookup 机制三大贡献，Engram 继承了查表思想，只是把 product key 换成了 hash。

  1. N-Grammer 生成 bigram 时词表会从 $V$ 爆炸到 $V^2$，codebook 是怎么解决的？（对应：Codebook）

答案： 用 k-means 聚类对词表降维。原始 unigram 词表 32000 的话，bigram 词表是 $32000^2$≈10 亿，不可行；N-Grammer 把 token embedding 聚成 4096 个 codebook vector，语义相似的 token 共用一个 id，词表压到 4096，bigram 词表就变成 $4096^2$≈1600 万，可以接受。之后把相邻 token 的 codebook id 组合成 bigram id，再用对随机质数取模的 hash 做 $O(1)$ 查表。DeepSeek 的 tokenizer 压缩目标相同但手段更简单，直接按大小写和拼写规则归并。

  1. Engram 架构中 gating 起什么作用？有什么证据说明它学到了东西？（对应：门控机制）

答案： gating 控制检索到的 n-gram 信息有多少进入输出：查出的 embedding 经两个 linear projection 得到 key 和 value，原始输入当 query，scaled dot product 算出 $\alpha$，$\alpha$ 乘 value——$\alpha$ 越大信息进入越多，相当于给可能带噪音的检索结果加了过滤阀门。证据是论文的 $\alpha$ 热力图：红色高亮处正好是固定搭配，如 Diana 与 the princess of Wales、「四大」与「发明」、「造纸」与「术」、「仲景」与「张」。这一机制由 Meta 在 memory layer 上首先引入，Engram 直接沿用，连 activation function 都一样。

  1. Engram 的知识检索为什么比 FFN 的计算方式快？它做了哪些工程保证？（对应：Hash 查表）

答案： 因为它把「simulating retrieval through computation」换成了直接查表：FFN 方式每层都要做内积相似度计算和加权平均，而 Engram 对 2-gram/3-gram 做 hash，复杂度约 $O(1)$，几乎不耗 FLOPs。工程上有三个保证：tokenizer 压缩用规则归并大小写变体缩小词表；multi-head hash n-gram 用多个不同 hash function（每路是简单异或）避免 collision；巨大的 embedding 表训练时跨 GPU 共享、推理时 offload 到 CPU memory，再按记忆层级把常见 n-gram 放快内存、不常见的放慢内存。

  1. 消融实验里去掉 Engram 后哪类任务性能下降最多？这说明了什么？（对应：知识神经元）

答案： 需要 factual knowledge 的任务下降最多，其次是算法与数学类 reasoning 任务，阅读理解和常识推理类任务下降不明显。这说明 Engram 的主要贡献在知识的存储与提取：固定事实原本要靠 FFN 里知识神经元式的逐层计算来「回想」，现在由 n-gram 查表直接给出。这也与 MoE/Engram 的 U 型分配实验一致——Engram 作为 MoE 的补充专管条件记忆，事实类任务自然最依赖它。

答案： 用 k-means 聚类对词表降维。原始 unigram 词表 32000 的话，bigram 词表是 $32000^2$≈10 亿，不可行；N-Grammer 把 token embedding 聚成 4096 个 codebook vector，语义相似的 token 共用一个 id，词表压到 4096，bigram 词表就变成 $4096^2$≈1600 万，可以接受。之后把相邻 token 的 codebook id 组合成 bigram id，再用对随机质数取模的 hash 做 $O(1)$ 查表。DeepSeek 的 tokenizer 压缩目标相同但手段更简单，直接按大小写和拼写规则归并。

  1. Engram 架构中 gating 起什么作用？有什么证据说明它学到了东西？（对应：门控机制；第 1 集第 5 题）

答案： gating 控制检索到的 n-gram 信息有多少进入输出：查出的 embedding 经两个 linear projection 得到 key 和 value，原始输入当 query，scaled dot product 算出 $\alpha$，$\alpha$ 乘 value——$\alpha$ 越大信息进入越多，相当于给可能带噪音的检索结果加了过滤阀门。证据是论文的 $\alpha$ 热力图：红色高亮处正好是固定搭配，如 Diana 与 the princess of Wales、「四大」与「发明」、「造纸」与「术」、「仲景」与「张」。这一机制由 Meta 在 memory layer 上首先引入，Engram 直接沿用，连 activation function 都一样。

  1. Engram 的知识检索为什么比 FFN 的计算方式快？它做了哪些工程保证？（对应：Hash 查表；第 1 集第 6 题）

答案： 因为它把「simulating retrieval through computation」换成了直接查表：FFN 方式每层都要做内积相似度计算和加权平均，而 Engram 对 2-gram/3-gram 做 hash，复杂度约 $O(1)$，几乎不耗 FLOPs。工程上有三个保证：tokenizer 压缩用规则归并大小写变体缩小词表；multi-head hash n-gram 用多个不同 hash function（每路是简单异或）避免 collision；巨大的 embedding 表训练时跨 GPU 共享、推理时 offload 到 CPU memory，再按记忆层级把常见 n-gram 放快内存、不常见的放慢内存。

  1. 消融实验里去掉 Engram 后哪类任务性能下降最多？这说明了什么？（对应：知识神经元；第 1 集第 7 题）

答案： 需要 factual knowledge 的任务下降最多，其次是算法与数学类 reasoning 任务，阅读理解和常识推理类任务下降不明显。这说明 Engram 的主要贡献在知识的存储与提取：固定事实原本要靠 FFN 里知识神经元式的逐层计算来「回想」，现在由 n-gram 查表直接给出。这也与 MoE/Engram 的 U 型分配实验一致——Engram 作为 MoE 的补充专管条件记忆，事实类任务自然最依赖它。
